# 布尔、单选与多选推理方案

更新日期：2026-09-28。本文记录当前推理方案及待实现约定。多选采用共享前缀、每项独立 Y/N；其效率、数值一致性及业务效果尚待验证，不作为最终最优架构结论。

## 状态与范围

| 模式 | 设计 | 实现与验证 |
|---|---|---|
| 布尔 | 一对标签，sigmoid 分数差 | 已实现；已有 HTTP 和前向对照记录 |
| 单选 | K 个标签，候选内 softmax，选择一项 | 尚未实现或验证 |
| 多选 | 共享前缀，K 个隔离的 Y/N 问题分支，各自评分后按阈值选集合 | 尚未实现或验证 |

当前 POST `/v1/decide` 仍只接收原有 query、criterion、image，返回布尔结果。本文不新增实际 API 字段、路由或运行代码。数学定义见 [数学模型](mathematics.md)。

## 执行结构

布尔和单选保留各自单个答案位置的读出。多选执行以下流程：

1. 应用提供材料、图片、规则和全部业务候选；服务内置系统提示词。
2. 对顺序无关的任务，按业务 ID 规范化候选展示，构造公共前缀。
3. 处理公共前缀一次，保存完整可复用模型状态。
4. 每个候选追加自己的短问题：“在上述材料、规则及完整候选下，这一项是否应该选中？Y=是，N=否。”
5. 各分支从相同前缀状态独立出发，可按资源预算批量执行；每个分支读取自己的首答案位置 Y/N logits。
6. 分别计算 sigmoid 分数差、应用阈值、按业务 ID 汇总。

前缀只处理一次不代表整次多选只有一次模型前向。每个分支仍有后缀计算；分支不得读取其他分支答案。当前不新增训练参数、不生成解释或答案序列，不枚举全部答案组合。

## 首版工程约定（待实现）

### 候选与标签

- 单选至少 2 项，多选至少 1 项；每项包含唯一、非空的字符串 ID 和非空描述。完全重复的 ID 拒绝，不自动改名或合并；描述重复不代表业务 ID 相同。
- 单选标签池候选顺序为 `A–Z`、`a–z`，由固定 tokenizer 验证可往返单 token、非特殊且 ID 互异；设通过校验的标签数为 L，单选最多 L 项，不静默截断或分组。
- 单选按业务 ID 的 Unicode 码点字典序分配内部标签；映射在提示词中明确展示。
- 多选每个分支统一使用同一对 Y/N token，仅需两个可用标签，候选数不受标签池数量约束。候选数上限需由输入预算、分支预算和资源实测确定，本次不承诺具体数值；实现前必须配置有限上限并在超限时拒绝。
- 多选公共候选列表和内部调度按业务 ID 的 Unicode 码点字典序规范化。仅适用于不依赖调用方原始顺序的任务；依赖顺序的标准不在该约定的支持范围。
- 每个完整分支必须经实际聊天模板和 tokenizer 核验公共 token 前缀、位置与图像元数据。Y/N 单 token 资格由程序检查，不是靠提示词保证。

### 分数与决策

- 布尔和多选默认阈值 0.5，严格大于才选中；等于时返回 false/不选中。现有布尔 API 阈值仍固定，不因本方案变更。
- 未来多选接受全局阈值及按业务 ID 的覆盖值：逐项覆盖优先，其次全局值，最后默认 0.5。只接受有限的 [0,1] 数值；覆盖表出现不存在的 ID 时拒绝。阈值不是概率校准参数。
- 单选比较未经舍入的 logits；完全同分时选业务 ID 字典序最小的一项。布尔保持既有同分返回 false 的规则，不通过通用单选平分规则改变它。
- 多选允许零项或全部选中；结果列表按请求中的候选顺序输出。候选数量限制、互斥约束、top-k 策略不自动添加。
- 分数用数值稳定算法计算，不先对 logits 作采样温度、top-k 或重复惩罚。非有限 logits 视为推理失败，不返回伪造的均匀概率或 false。
- 保留 `calibrated: false`，同时记录原始分数差、模型 revision、模板版本和实际阈值，便于复现。输出分数是命题判断的代理，不承诺真实事件概率或整体逻辑一致。

### 资源与异常

- 当前 API 的图片及输入预算继续有效；未来多选需额外配置候选数及分支并发预算。完整候选和每个后缀都计入对应输入长度，不静默删除选项。
- 公共缓存只读共享或采用写时复制；分支的追加缓存、位置计数及循环状态隔离。Qwen3.5 等混合架构需处理完整状态，不能只共享注意力 KV。
- 服务保持一个模型请求执行单元；请求内部的分支可串行、分批或并行。不能把 K 个分支的批量执行宣称为无额外成本的一次判断。
- 字段无效、重复 ID、阈值错误、标签不可用或资源预算超限应在推理前拒绝。任一分支失败时整次请求报告错误，不悄悄将失败项设为 false 或省略。
- 树状注意力/分支打包仅作为潜在优化，是否适配当前后端与混合架构需另行验证。

## 待执行实验与验收

本次仅定义实验要求，未编写或运行多选测试。

1. **数值参考**：逐项处理完整分支输入，记录 Y/N logits；共享缓存的串行、批处理路径分别与其比较，预先声明容差，记录分数和决策差异。
2. **状态隔离**：改变分支执行顺序、先后运行不同请求，检查缓存及位置状态是否污染结果。验证图片编码/前缀真正复用，不只观察总体耗时。
3. **多标签行为**：混合正负、全部成立、全部不成立样例及图像对照，验证每个分支询问的是当前候选是否入选。
4. **输入排列**：仅改变调用方顺序，检查规范化后的 token 输入和按业务 ID 对齐的结果。另测改变规范展示顺序产生的偏差，不将后者误当作规范化已解决。
5. **性能**：固定材料/图片，改变候选数量、公共前缀长度和分支批量大小；与 K 次完整问答相比，记录前缀及后缀耗时、缓存开销、端到端延迟和峰值内存。
6. **语义及集合关系**：测试规则例外、候选关联和提示注入；逐项判断正确与整组约束满足分别统计。机制通过不代表业务有效。

尚未测得加速比或设定业务验收阈值。训练、校准、联合概率建模与服务器表现不在本次文档变更范围。
