# 数学模型

更新日期：2026-09-28。布尔推理已实现并验证；单选与多选的下述模型是已确定的首版推理设计，尚未实现或进行效果验证。训练公式仅说明未来兼容性，不构成本次训练方案。

## 1. 统一输入及独立问题

统一输入包含内置系统提示词 S_mode、图文材料 X、评价标准 R、动态候选列表 C 和程序分配的标签映射 M：

$$P=\operatorname{Template}(S_{mode},X,R,C,M),\qquad z=\operatorname{LMHead}_{\theta}(h)$$

h 是对 P 完成 prefill 后最后输入位置的隐藏表示。三个模式使用同一模型前向路径，但使用不同的答案映射和归一化。系统提示词由服务按模式选择，不由请求覆盖。候选及其标签映射必须完整出现在输入中。

当前布尔模式令固定系统提示词为 S，待审文本与可选图像为 X，评价标准为 R。模板构造 P = Template(S, R, X, A=是, B=否)，并在助手开始回答的位置结束。评价标准由调用方的应用逻辑控制；待审材料不应成为执行指令。当前 API 每请求处理一个布尔问题。

若将来有多个标准 R_i，则每个标准构成独立输入 P_i。批处理可以提升效率，但不改变各问题定义，也不表示这些事件统计独立。

## 2. Prefill 与原有输出头

文本经过分词，图像经过视觉处理器。固定参数 θ 的模型前向处理全部输入，得到最后一个输入位置的最终隐藏表示 h：

$$h = \operatorname{Backbone}_{\theta}(\operatorname{Processor}(P))_{\mathrm{last}}$$

原模型的语言输出头给 token 评分：

$$z_A=w_A^\top h+b_A,\qquad z_B=w_B^\top h+b_B$$

这是模型训练好的线性评分，不是余弦相似度。无偏置的模型取 b=0。当前模型共享输入 embedding 与输出权重；代码调用原 embedding 的 as_linear，仅在最后位置计算词表分数，再提取 A/B。标签必须是经过 tokenizer 校验的不同单 token。

Prefill 已能产生第一个答案位置的分数。只有要继续生成第二个及后续 token 时，才需将选中 token 再送入模型。本 API 不需要这个生成循环。

## 3. 二选一概率与布尔结果

$$d=z_A-z_B$$

$$p_{yes}=\frac{e^{z_A}}{e^{z_A}+e^{z_B}}=\sigma(d),\qquad p_{no}=1-p_{yes}$$

这里是“给定输入，且下一个 token 被限定在 A/B 集合内”的条件概率。它忽略词表其余 token 的概率质量，不能直接解释为真实违规发生概率或答案正确率。

$$\hat y=\mathbf{1}[p_{yes}>0.5]=\mathbf{1}[d>0]$$

相等时返回 false。实现使用数值稳定的 sigmoid，不对分数加采样温度、top-k 或重复惩罚。运行错误与 false 分开处理。

## 4. 单选推理模型（已确定设计，尚未实现）

单选将布尔判断的两个答案扩展为 K 个互斥候选，仍然读取同一个“下一个 token”位置。它不要求增训、更换输出头或生成答案文本。当前 API 仍仅实现第 3 节的布尔输出。

### 4.1 业务选项与内部标签

令候选列表为：

$$C=[c_1,\ldots,c_K],\qquad c_i=(u_i,d_i),\qquad K\geq 2$$

其中 u_i 是唯一的业务 ID，d_i 是选项的语义描述。程序为每项分配不同的内部标签 ℓ_i，例如 A、B、C、D，并保存双向映射：

$$u_i\longleftrightarrow\ell_i\longleftrightarrow t_i$$

t_i 是标签对应的 token ID。标签不是新增 token，也不需要新增词表或权重；它们来自现有 tokenizer。程序必须验证每个标签编码后恰好是一个 token、解码可还原标签，且各 token ID 不同。候选数量受实际验证可用的标签数量限制，不假定任何模型都支持相同数量。

业务 ID 可以是 billing、shipping 等任意应用标识，不要求它们本身是单 token。例如：

| 业务 ID | 语义描述 | 程序分配的内部标签 |
|---|---|---|
| billing | 账单问题 | A |
| shipping | 物流问题 | B |
| technical | 技术问题 | C |

### 4.2 输入组装

固定系统提示词 S_choice 规定任务是单选、只回答内部标签，以及待审材料不构成指令。本次评价标准、完整候选及标签含义由程序写入受控请求模板：

$$M=[(\ell_1,d_1),\ldots,(\ell_K,d_K)]$$

$$P=\operatorname{Template}(S_{choice},R,X,M)$$

标签与含义必须在模型可见的提示词中明确对应；“标签是单 token”由 tokenizer 校验保证，不能靠系统提示词保证。完整候选列表参与模型判断，不把每个选项从上下文中单独拿出来判断。

### 4.3 同一答案位置的评分与归一化

沿用第 2 节的前向路径，得到最后输入位置的隐藏表示 h 和原输出头的词表分数 z。提取每个标签的分数：

$$s_i=z[t_i]=w_{t_i}^{\top}h+b_{t_i}$$

在 K 个候选之间做 softmax；为数值稳定，计算时减去最大分数 m：

$$m=\max_j s_j,\qquad p_i=\frac{\exp(s_i-m)}{\sum_{j=1}^{K}\exp(s_j-m)}$$

$$\sum_{i=1}^{K}p_i=1,\qquad \hat i\in\operatorname*{arg\,max}_i p_i$$

一次完整输入的 prefill 即可取得所有候选的分数，不需要为 K 个选项分别执行 K 次完整前向。输出的业务选项为对应的业务 ID，而不是内部字母；各项分数也按业务 ID 返回。若最高分完全相同，首版设计选择业务 ID 按 Unicode 码点字典序最小的一项；该规则不依赖候选展示顺序，但不能消除模型本身的顺序偏差。

建议响应语义为：

```json
{
  "choice": "billing",
  "probabilities": {"billing": 0.80, "shipping": 0.05, "technical": 0.15},
  "calibrated": false
}
```

这些值表示给定当前输入、且下一个 token 被限制在内部标签集合中时的条件概率，不能直接当作现实事件概率或正确率。系统必选一项；若允许“都不符合”或“信息不足”，调用方需将它明确列入候选，并给出判定含义。

布尔判断是 K=2 的特例：A=是、B=否时，p_A=σ(s_A−s_B)。当前布尔实现相等时返回 false，扩展单选时需保留该已存在的行为边界。

### 4.4 顺序和编码的一致性边界

对语义不依赖选项顺序的任务，换序或更换内部标签后，按业务 ID 对齐的结果应保持一致。若 π 表示重排，理想的分数输出满足排列等变性：

$$f(X,R,\pi C)=\pi f(X,R,C)$$

这是待检查的性质，不是现有模型或 softmax 自动提供的保证。选项位置、编码和完整候选集合均可能影响模型分数；特别是在平分情况下，确定性选取一项也不自动保证排列等变性。当前尚未实现针对这些性质的系统检查或训练约束。

## 5. 多选：同位置成对 logits（已确定设计，尚未实现）

### 5.1 标签映射与一次前向

令 C=[c_1,…,c_K]，K≥1，每项包含唯一业务 ID u_i 与描述 d_i。程序为每项分配一对标签，分别表示该项应选中和不应选中：

$$M=\{(u_i,d_i,\ell_i^+,\ell_i^-)\}_{i=1}^{K}$$

全部 2K 个标签必须对应互不相同、已校验的单 token ID。它们不是新建词表项，不新增输出头参数。

| 业务候选 | 选中标签 | 不选中标签 |
|---|---|---|
| insult：包含辱骂 | A | B |
| threat：包含威胁 | C | D |
| personal_data：包含个人信息 | E | F |

材料、规则、完整候选及上述映射共同进入一次 prefill。多选模板明确说明允许多项成立，并定义每对标签的含义；读取的是同一个首答案位置上全部标签的分数，不生成标签列表，也不为各项分别执行问答。

$$z_i^+=z[t_i^+],\qquad z_i^-=z[t_i^-],\qquad \Delta_i=z_i^+-z_i^-$$

### 5.2 成对归一化与集合输出

$$p_i=\frac{\exp(z_i^+)}{\exp(z_i^+)+\exp(z_i^-)}=\sigma(\Delta_i)$$

每一对内部的 yes/no 分数合计为 1，各候选的 p_i 不要求合计为 1，也不再做跨候选 softmax。

若词表完整 softmax 为 q_t=exp(z_t)/Z，则：

$$p_i=\frac{q_{t_i^+}}{q_{t_i^+}+q_{t_i^-}}$$

Z 在比值中抵消，故词表归一化不阻止多个候选同时取得高分。实现应直接从 logits 用稳定 sigmoid 计算，避免低概率 token 下溢。不能对单个候选 token 的原始 logit 直接作 sigmoid 来代替成对差值。

每项应用阈值 τ_i：

$$\hat y_i=\mathbf 1[p_i>\tau_i],\qquad \hat S=\{u_i:\hat y_i=1\}$$

默认 τ_i=0.5，相等时不选中；允许空集合，也允许全部选中。不自动强制 top-k、不自动把空集合改成最高分项。

建议的输出语义示例（不是当前已上线 API）：

```json
{
  "selected": ["insult", "threat"],
  "scores": {"insult": 0.982, "threat": 0.881, "personal_data": 0.047},
  "thresholds": {"insult": 0.5, "threat": 0.5, "personal_data": 0.5},
  "calibrated": false
}
```

### 5.3 分数解释与能力边界

p_i 是在该候选自己的正负 token 对内归一化的 next-token 分数。它作为模型对命题的判断代理；尚不能认定等于 P(候选 i 应选中 | 材料、规则、完整候选)。数学上可表达一组任意的 0～1 分数，不等于现有权重已经学会该读出约定。

尤其需要验证：只有一对标签获得大部分词表概率质量时，其他低概率质量的标签对的相对比值可能仍然非常尖锐。成对归一化不保证证据充分、置信度可靠或跨选项逻辑一致。候选共享上下文和模型表示，不假设事件独立，也不提供完整答案集合的联合分布；不能将各项概率相乘冒充联合概率。

### 5.4 计算复杂度

一次请求使用一次共享 prefill，同一答案位置读取 2K 个 logits，后处理 O(K)。不枚举 2^K 个组合，不执行 K 个完整问答，不生成 K 个答案 token。候选列表会增加输入长度，因此模型计算并非对 K 恒定。首版可沿用完整词表输出头后提取标签，后续仅计算选中权重行属于另行优化。

布尔读出与 K=1 的成对多选在代数上相同，但不同提示词模板的实际分数不保证相等；单选则采用候选间竞争的 softmax，不能直接作为多选成员概率。

## 6. 检查机制与未来训练接口（尚未实现）

排列和标签重编码应保持任务含义；按业务 ID 对齐后检查决策及分数漂移。语义依赖位置的标准不适用排列不变要求。该检查是实验要求，不是现有模型保证。

后续如增训，多选可直接沿用当前读出位置与配对定义：

$$\mathcal L_{pair}=-\sum_i[y_i\log p_i+(1-y_i)\log(1-p_i)]$$

应使用每对 logits 的归一化目标，不能把所有正标签当作同一个 next-token softmax 中的唯一正确答案。动态候选、标签分配、选项数量和顺序的覆盖，以及一致性约束，均属于后续训练设计。当前不确定训练配方或最优损失。

可独立预留概率校准与业务阈值：

$$p_i=\sigma(\Delta_i/T_i+\beta_i),\qquad T_i>0$$

本版设计使用 T_i=1、β_i=0；当前布尔实现也不做校准。模型训练更新 θ，校准拟合 T/β，阈值选择调整 τ；三者不同。训练损失本身不保证部署分布校准。多规则的业务布尔值可用 OR/AND 组合；需要互斥、数量、包含关系时须另行定义，本版不自动加入组合修正。
