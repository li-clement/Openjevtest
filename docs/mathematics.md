# 数学模型

更新日期：2026-09-29。第 1–6 节保留二分类、单选和共享前缀多选设计；其中仅二分类 API 已实现。第 7 节追加支持弃权的三态数学架构，第 8 节定义可训练门控扩展。三态推理、校准、门控和后训练均尚未实现或验证；文中的训练目标是研究设计，不是已完成的训练配方。

## 1. 统一输入及独立问题

统一输入包含内置系统提示词 S_mode、图文材料 X、评价标准 R、动态候选列表 C 和程序分配的标签映射 M：

$$P=\operatorname{Template}(S_{mode},X,R,C,M),\qquad z=\operatorname{LMHead}_{\theta}(h)$$

h 是对应判断上下文完成前向计算后最后输入位置的隐藏表示。布尔与单选分别读取一个答案位置；多选读取共享前缀后各分支自己的答案位置。系统提示词由服务按模式选择，不由请求覆盖。候选及其标签映射必须完整出现在输入中。

当前布尔模式令固定系统提示词为 S，待审文本与可选图像为 X，评价标准为 R。模板构造 P = Template(S, R, X, A=是, B=否)，并在助手开始回答的位置结束。评价标准由调用方的应用逻辑控制；待审材料不应成为执行指令。当前 API 每请求处理一个布尔问题。

若将来有多个标准 R_i，则每个标准构成独立输入 P_i。批处理可以提升效率，但不改变各问题定义，也不表示这些事件统计独立。

## 2. Prefill 与原有输出头

文本经过分词，图像经过视觉处理器。固定参数 θ 的模型前向处理全部输入，得到最后一个输入位置的最终隐藏表示 h：

$$h = \operatorname{Backbone}_{\theta}(\operatorname{Processor}(P))_{\mathrm{last}}$$

原模型的语言输出头给 token 评分：

$$z_A=w_A^\top h+b_A,\qquad z_B=w_B^\top h+b_B$$

这是模型训练好的线性评分，不是余弦相似度。无偏置的模型取 b=0。当前模型共享输入 embedding 与输出权重；代码调用原 embedding 的 as_linear，仅在最后位置计算词表分数，再提取 A/B。标签必须是经过 tokenizer 校验的不同单 token。

Prefill 已能产生第一个答案位置的分数。只有要继续生成第二个及后续 token 时，才需将选中 token 再送入模型。本 API 不需要这个生成循环。

## 3. 二选一概率与布尔结果

$$d=z_A-z_B$$

$$p_{yes}=\frac{e^{z_A}}{e^{z_A}+e^{z_B}}=\sigma(d),\qquad p_{no}=1-p_{yes}$$

这里是“给定输入，且下一个 token 被限定在 A/B 集合内”的条件概率。它忽略词表其余 token 的概率质量，不能直接解释为真实违规发生概率或答案正确率。

$$\hat y=\mathbf{1}[p_{yes}>0.5]=\mathbf{1}[d>0]$$

相等时返回 false。实现使用数值稳定的 sigmoid，不对分数加采样温度、top-k 或重复惩罚。运行错误与 false 分开处理。

## 4. 单选推理模型（已确定设计，尚未实现）

单选将布尔判断的两个答案扩展为 K 个互斥候选，仍然读取同一个“下一个 token”位置。它不要求增训、更换输出头或生成答案文本。当前 API 仍仅实现第 3 节的布尔输出。

### 4.1 业务选项与内部标签

令候选列表为：

$$C=[c_1,\ldots,c_K],\qquad c_i=(u_i,d_i),\qquad K\geq 2$$

其中 u_i 是唯一的业务 ID，d_i 是选项的语义描述。程序为每项分配不同的内部标签 ℓ_i，例如 A、B、C、D，并保存双向映射：

$$u_i\longleftrightarrow\ell_i\longleftrightarrow t_i$$

t_i 是标签对应的 token ID。标签不是新增 token，也不需要新增词表或权重；它们来自现有 tokenizer。程序必须验证每个标签编码后恰好是一个 token、解码可还原标签，且各 token ID 不同。候选数量受实际验证可用的标签数量限制，不假定任何模型都支持相同数量。

业务 ID 可以是 billing、shipping 等任意应用标识，不要求它们本身是单 token。例如：

| 业务 ID | 语义描述 | 程序分配的内部标签 |
|---|---|---|
| billing | 账单问题 | A |
| shipping | 物流问题 | B |
| technical | 技术问题 | C |

### 4.2 输入组装

固定系统提示词 S_choice 规定任务是单选、只回答内部标签，以及待审材料不构成指令。本次评价标准、完整候选及标签含义由程序写入受控请求模板：

$$M=[(\ell_1,d_1),\ldots,(\ell_K,d_K)]$$

$$P=\operatorname{Template}(S_{choice},R,X,M)$$

标签与含义必须在模型可见的提示词中明确对应；“标签是单 token”由 tokenizer 校验保证，不能靠系统提示词保证。完整候选列表参与模型判断，不把每个选项从上下文中单独拿出来判断。

### 4.3 同一答案位置的评分与归一化

沿用第 2 节的前向路径，得到最后输入位置的隐藏表示 h 和原输出头的词表分数 z。提取每个标签的分数：

$$s_i=z[t_i]=w_{t_i}^{\top}h+b_{t_i}$$

在 K 个候选之间做 softmax；为数值稳定，计算时减去最大分数 m：

$$m=\max_j s_j,\qquad p_i=\frac{\exp(s_i-m)}{\sum_{j=1}^{K}\exp(s_j-m)}$$

$$\sum_{i=1}^{K}p_i=1,\qquad \hat i\in\operatorname*{arg\,max}_i p_i$$

一次完整输入的 prefill 即可取得所有候选的分数，不需要为 K 个选项分别执行 K 次完整前向。输出的业务选项为对应的业务 ID，而不是内部字母；各项分数也按业务 ID 返回。若最高分完全相同，首版设计选择业务 ID 按 Unicode 码点字典序最小的一项；该规则不依赖候选展示顺序，但不能消除模型本身的顺序偏差。

建议响应语义为：

```json
{
  "choice": "billing",
  "probabilities": {"billing": 0.80, "shipping": 0.05, "technical": 0.15},
  "calibrated": false
}
```

这些值表示给定当前输入、且下一个 token 被限制在内部标签集合中时的条件概率，不能直接当作现实事件概率或正确率。系统必选一项；若允许“都不符合”或“信息不足”，调用方需将它明确列入候选，并给出判定含义。

布尔判断是 K=2 的特例：A=是、B=否时，p_A=σ(s_A−s_B)。当前布尔实现相等时返回 false，扩展单选时需保留该已存在的行为边界。

### 4.4 顺序和编码的一致性边界

对语义不依赖选项顺序的任务，换序或更换内部标签后，按业务 ID 对齐的结果应保持一致。若 π 表示重排，理想的分数输出满足排列等变性：

$$f(X,R,\pi C)=\pi f(X,R,C)$$

这是待检查的性质，不是现有模型或 softmax 自动提供的保证。选项位置、编码和完整候选集合均可能影响模型分数；特别是在平分情况下，确定性选取一项也不自动保证排列等变性。当前尚未实现针对这些性质的系统检查或训练约束。

## 5. 多选：共享前缀，每项独立 Y/N（当前方案，尚未实现）

### 5.1 公共上下文与候选问题

令 C=[c_1,…,c_K]，K≥1，每项包含唯一业务 ID u_i 与语义描述 d_i。所有分支保留完整候选上下文，在相同规则下分别判断某项是否应该入选，不让分支看到其他分支的答案。

对语义不依赖列表顺序的任务，程序按业务 ID 的 Unicode 码点字典序规范化候选列表：

$$C^*=\operatorname{Canonicalize}(C)$$

构造公共前缀 P_0，再构造各候选的问题后缀 Q_i：

$$P_0=\operatorname{PrefixTemplate}(S_{multi},X,R,C^*)$$

$$Q_i=\operatorname{QuestionTemplate}(u_i,d_i,\text{Y=应选中，N=不应选中})$$

语义上，每个完整分支输入为 P_i=P_0\oplus Q_i。所有分支使用同一对 Y/N token ID，且须校验它们为不同、可往返的非特殊单 token。不需要为不同候选分配不同的输出标签。

P_0 和 Q_i 表示模型实际输入 token 序列的切分，不是随意拼接的字符串。实现必须确认各完整聊天模板/图片处理结果拥有相同的 token 前缀及相同的位置元数据；若字符串分词边界改变，须退回实际共同 token 前缀。分支答案位置位于各自助手开始回答处，关闭思考。

### 5.2 缓存与隔离分支计算

公共前缀执行一次，保留可继续计算的完整状态：

$$\mathcal K_0=\operatorname{PrefillState}_{\theta}(P_0)$$

各分支从逻辑上独立的相同初始状态出发：

$$h_i=\operatorname{Forward}_{\theta}(Q_i;\operatorname{Fork}(\mathcal K_0))_{\mathrm{last}}$$

$$z_i=\operatorname{LMHead}_{\theta}(h_i)$$

Fork 表示分支隔离，并不要求物理复制全部缓存。支持只读共享/写时复制的后端可共享前缀存储；分支追加内容、位置计数和可变状态必须互不污染。对 Qwen3.5 等混合架构，状态不只包括注意力 KV，还包括其他层所需的循环状态等，必须完整处理。

分支可按内存预算串行、分批或并行执行。批处理和树状打包属于执行优化，不改变每个分支的是非问题语义；树状注意力不自动覆盖混合架构状态。当前尚未实现这些路径，也没有测得加速比。

### 5.3 分支评分与集合输出

在第 i 个分支自己的首答案位置，读取相同的 Y/N token：

$$\Delta_i=z_i[t_Y]-z_i[t_N]$$

$$p_i=\sigma(\Delta_i)=\frac{\exp(z_i[t_Y])}{\exp(z_i[t_Y])+\exp(z_i[t_N])}$$

各分支内部 yes/no 合计为 1，各候选的 p_i 不要求合计为 1。p_i 是给定完整分支上下文、限定下一个 token 为 Y/N 时的条件分数，作为当前候选入选判断的代理；未经校准，不承诺等于真实事件概率或正确率。

$$\hat y_i=\mathbf 1[p_i>\tau_i],\qquad \hat S=\{u_i:\hat y_i=1\}$$

默认 τ_i=0.5，相等时不选中；允许空集合与全部选中，不自动强制 top-k。输出按业务 ID 汇总，例如（仅展示语义，不是当前 API）：

```json
{
  "selected": ["insult", "threat"],
  "scores": {"insult": 0.90, "threat": 0.80, "personal_data": 0.10},
  "thresholds": {"insult": 0.5, "threat": 0.5, "personal_data": 0.5},
  "calibrated": false
}
```

独立执行分支不意味着候选事件统计独立。它们均读取完整候选上下文，但逐项判断不保证互斥、数量限制等集合关系；不提供完整联合分布，也不能将各项分数直接相乘作为联合概率。

### 5.4 计算量与等价性要求

计算目标是“一次公共前缀 + K 个问题后缀”，不是一次前向同时得到所有结果：

$$T_{serial}\approx T_{prefix}+\sum_i T_{suffix,i}$$

此式仅表示串行工作分解，不是测得的运行时间。各后缀仍需读取公共历史并通过模型各层，批量执行也不会消除这些计算。收益取决于公共前缀长度、候选数、缓存复制成本、图片处理复用和后端内核效率。候选列表本身也使公共前缀随 K 增长。

与 K 次完整计算相比，共享前缀直接消除重复工作。以公共成本 P 和近似相同的后缀成本 S 表示，忽略管理开销：K(P+S) → P+KS，减少 (K−1)P。分支并行是进一步改善执行时间的机制，可能增加内存；不应把减少计算量与并行加速混为一谈。理论上的重复工作削减明确，实际加速倍数待测。

正确缓存复用的目标是：各分支 logits 与分别处理完整 P_i 的参考路径，在声明的数值容差内一致；以实际测试确认，不能仅凭缓存命中判定正确。整个过程不采样答案、不将某分支生成的答案接入其他分支，也不枚举所有答案组合。

### 5.5 请求换序与位置偏好的边界

若业务 ID、描述、材料和规则不变，仅输入候选的排列变化，规范化后 P_0 和各 Q_i 相同。在确定性执行和相同数值路径条件下，按业务 ID 对齐的分数应相同。内部调度采用规范顺序，结果再映射到调用方顺序。

这只消除调用方排列变化造成的输入差异，不证明模型没有位置偏好，也不保证改名、改写描述、增加候选后分数不变。模型仍看到一种固定的线性顺序。语义明确依赖原始列表顺序的任务不适用此规范化约定，不应静默改写任务。

## 6. 检查机制与未来训练接口（尚未实现）

当前重点是分支隔离、缓存路径与完整输入路径的一致性、图文参与、请求换序稳定性及实际效率。更换规范顺序、改写候选等属于独立的模型敏感性实验，不作为规范化自动保证。

如未来进行增训，可直接使用各分支读出的 p_i 与标注 y_i：

$$\mathcal L_{branch}=-\sum_i[y_i\log p_i+(1-y_i)\log(1-p_i)]$$

这只是与推理接口兼容的候选目标，不是已确定训练方案。可独立预留校准与阈值选择：

$$p_i=\sigma(\Delta_i/T_i+\beta_i),\qquad T_i>0$$

当前方案 T_i=1、β_i=0。模型训练更新 θ、校准拟合 T/β、业务阈值选择调整 τ；三者不同。训练损失不自动保证泛化或概率校准。业务关系可在规则中明确，但跨分支逻辑一致性仍需评估。


## 7. 新版：支持弃权的三态判断与信念输出

### 7.1 既有二分类的边界

第 3 节只在两个答案之间分配分数，并强制返回布尔值。其局限是：没有显式弃权标签；Y/N 的相对优势不能单独识别缺乏判断依据的输入；输出格式正确与分数归一化不保证判断正确、信念可靠或跨任务泛化。

新版在原有词表中增加一个模型可见的弃权答案，仍复用同一主干和原输出头。推理先决定是否弃权，再决定 Y/N，同时保留支持所选答案的分数。它是独立的三态契约，不静默改变现有布尔 API，也不自动扩展第 5 节的多选实现。

### 7.2 输入、标签与参数

定义一次请求：

$$x=(Q,I,R),\qquad P=\operatorname{Template}(S,Q,I,R,M)$$

Q 为待判断文本，I 为可选图像，R 为评价标准，S 为服务内置系统提示词，M 为标签与语义的映射。

| 数学标签 | 语义 |
|---|---|
| Y | 根据材料和评价标准，判断为是 |
| N | 根据材料和评价标准，判断为否 |
| U | 缺乏足够判断依据，无法明确区分是与否，选择弃权 |

Y/N/U 是数学标签，不要求每个 tokenizer 都使用这三个字面字符。程序须为其选择现有词表中三个不同、可往返的非特殊单 token，并在提示词中明确映射。验证包括实际回答模板中的 token 边界；不能仅凭字符外观认定单 token。

模型已有参数记为 θ。推理时 θ 固定，不新增或重训语言输出头。训练阶段是否更新主干、使用适配器或冻结共享 embedding，属于后续训练配置；模型若绑定输入 embedding 与输出权重，须统一管理这组共享参数。

### 7.3 单次前向与原始分数

定义答案位置隐藏表示和三个输出分数：

$$h=\operatorname{Backbone}_{\theta}(\operatorname{Processor}(P))_{\mathrm{last}}\in\mathbb R^D$$

$$z_j=w_j^\top h+b_j\in\mathbb R,\qquad j\in\{Y,N,U\}$$

w_j 的转置为原语言输出矩阵中对应标签的一行，b_j 为对应偏置；无偏置模型省略该项。h 为高维向量，三个 z_j 各为标量。该投影不能保留 h 的全部信息，后续标量变换也不能恢复被丢弃的信息。

全部输入经过一次 prefill 后即可取得这三个分数，不采样答案 token，不进行答案生成循环。原有权重提供 token 预测能力；提示词赋予本次任务的标签含义，不意味着模型已经学会三态一致性。

### 7.4 信念分布与两个阶段分数

定义标签集合内的归一化分数：

$$Z=\sum_{j\in\{Y,N,U\}}e^{z_j},\qquad p_j=\frac{e^{z_j}}{Z},\qquad \sum_jp_j=1$$

定义弃权信念 u 与 Y/N 内部的是倾向 q：

$$u=p_U,\qquad q=\frac{p_Y}{p_Y+p_N}=\frac{e^{z_Y}}{e^{z_Y}+e^{z_N}}$$

反向关系为：

$$p_U=u,\qquad p_Y=(1-u)q,\qquad p_N=(1-u)(1-q)$$

u 表示模型在三项之间分配给 U 的支持；q 表示将答案限制在 Y/N 时对 Y 的相对支持。二者是模型在当前输入和参数下的一步信念，不直接等于真实事件概率、正确率或可迁移到任意任务的校准信心。q 不应解释为经过弃权筛选后的经验正确率。

三分类分布有两个自由度。三个 logits 的共同加性偏移不改变分布；u、q 保留该分布的信息，但不是隐藏向量 h 的无损表示。

### 7.5 固定阈值的两阶段决策

定义两个运行配置参数：

$$\tau_U,\tau_Y\in(0,1)$$

定义最终决策：

$$D(x;\tau_U,\tau_Y)=\begin{cases}
U,&u\geq\tau_U,\\
Y,&u<\tau_U\ \land\ q\geq\tau_Y,\\
N,&u<\tau_U\ \land\ q<\tau_Y.
\end{cases}$$

第一阶段比较 u 与弃权阈值；仅未触发弃权的请求进入第二阶段。第二阶段比较 q 与是非阈值。等号分别归 U 和 Y。两阶段是程序判断顺序，不是两次模型调用，不使用三分类 argmax 替代此规则。

τ_Y=0.5 是 Y/N 对称的中性分界，等价于 z_Y−z_N≥0 时选 Y；τ_Y 不应在 q 的刻度上设为 0。τ_U 无已验证的通用取值，两个部署阈值均需记录并按任务评估。此处的边界规则仅属于新版三态设计，现有二分类同分返回 false 的行为保持不变。

降低 τ_U 会扩大弃权范围；提高 τ_Y 会在通过第一阶段的请求中减少 Y。通过 U 门仅表示没有触发弃权，不保证 Y/N 的区分度已经足够大。按本契约，通过 U 门后必选 Y/N，不隐含第二个弃权区间。

### 7.6 所选答案支持度、优势与输出

定义所选 Y/N 答案的支持度 c：

$$c=\begin{cases}
q,&D=Y,\\
1-q,&D=N,\\
\mathrm{null},&D=U.
\end{cases}$$

对于 D≠U，定义所选答案相对另一答案的优势：

$$m=2c-1$$

m>0 表示模型更支持所选答案，m=0 表示支持相同，m<0 表示阈值策略选择了支持较低的一方。τ_Y≠0.5 时后者可以发生，不得取绝对值或强行将 c 提升到 0.5。c 与 m 仅是同一信息的不同刻度。

定义最小业务输出：

$$F_\theta(x;\tau_U,\tau_Y)=(D,u,c)$$

| 字段 | 数学量 | 含义 |
|---|---|---|
| decision | D | Y、N 或 U |
| unknown_belief | u | 三分类中的弃权信念 |
| selected_yn_belief | c | Y/N 内部对所选答案的支持；U 时为空 |

以下仅为拟议响应示例，不是已实现的 API。使用 τ_U=0.5、τ_Y=0.5、u=0.2、q=0.75：

```json
{
  "decision": "Y",
  "unknown_belief": 0.2,
  "selected_yn_belief": 0.75,
  "calibrated": false
}
```

该例的三分类分数为 p_Y=0.6、p_N=0.2、p_U=0.2。对于 Y/N 决策，三分类中所选答案的支持为 p_D=(1−u)c，与 c 含义不同，不能共用未注明口径的 confidence 字段。

诊断记录保留三个 logits、q、实际阈值、模型 revision、模板版本、标签 token ID 和门控配置版本。返回 U 时也保留 q 供分析；只将业务字段 c 置空，不丢弃原始读出信息。异常与 U 分开：非法输入、资源超限、非有限分数或后端失败均返回错误，不能伪装成模型弃权。

### 7.7 数值稳定实现

定义：

$$d=z_Y-z_N,\qquad r=z_U-\operatorname{LSE}(z_Y,z_N)$$

$$\operatorname{LSE}(a,b)=m_0+\log(e^{a-m_0}+e^{b-m_0}),\qquad m_0=\max(a,b)$$

于是：

$$q=\sigma(d),\qquad u=\sigma(r)$$

实际计算直接从 logits 求 q，避免 p_Y+p_N 因 U 极强而数值下溢时再做除法。sigmoid、logsumexp、softplus 使用稳定实现；决策比较使用未舍入分数。在有限精度下 u 或 q 可能饱和为 0/1，训练对数损失应从 logits 直接计算，而不是对舍入后的概率取对数。

### 7.8 一致性训练目标

定义训练标签 t∈{Y,N,U}，一致性权重 λ>0，以及均匀分布 v=(0.5,0.5)。候选逐样本损失为：

$$\mathcal L(x,t)=\begin{cases}
-\log p_Y,&t=Y,\\
-\log p_N,&t=N,\\
-\log u+\lambda D_{\mathrm{KL}}\big(v\Vert(q,1-q)\big),&t=U.
\end{cases}$$

期望训练行为为：Y 样本降低 u、提高 q；N 样本降低 u、降低 q；U 样本提高 u，并使 q 接近 0.5。U 样本的附加项将“无法明确区分”落实到 Y/N 信念，而不只是提高 U 的排名。这里的 (0.5,0.5) 是训练目标分布，不是推理阈值。

令 sp(a)=log(1+exp(a))，等价的稳定损失为：

$$\mathcal L_Y=\operatorname{sp}(r)+\operatorname{sp}(-d),\qquad
\mathcal L_N=\operatorname{sp}(r)+\operatorname{sp}(d)$$

$$\mathcal L_U=\operatorname{sp}(-r)+\lambda\left[\tfrac12\operatorname{sp}(-d)+\tfrac12\operatorname{sp}(d)-\log2\right]$$

该目标要求有明确语义的 U 标注或反馈。现有 Y/N 标签不能仅凭模型暂时答错就自动改成 U，否则会混淆任务标签、模型能力和弃权策略。U 数据来源、可回答性的判定方式、λ、参数更新范围及训练数据比例尚待确定。

这是已记录的候选训练方向，不是官方 Jev RLCD 的复现，也不预先指定必须使用 RL。仅训练 U 与 Y/N 的一致性不足以保证有用判断：始终弃权且 q=0.5 同样满足一致性，因此还须评估正确作答、错误作答和不必要弃权。有限数据训练不保证样本外校准、泛化或逐例一致。

### 7.9 一致性诊断、校准与阈值选择

高 u 与远离 0.5 的 q 同时出现，属于需要评估的信念不一致现象。保留原始分数和这种状态，不在推理时把 q 强制改成 0.5。阈值返回 U 只规定行动，不证明模型的信念已经自洽；三个读出分数也不足以定位隐藏层内的原因。

定义业务作答覆盖率与作答错误率：

$$\operatorname{Coverage}=\Pr(D\ne U),\qquad
\operatorname{Risk}=\Pr(D\ne y\mid D\ne U)$$

其中 y 是具备可靠 Y/N 参考答案的评估样本标签；Risk 不在没有作答的集合上定义。对有 U 标注的样本，还应单独报告应弃权却作答、可回答却弃权等结果，不能将 U 直接等同于一个错误的 Y/N 标签。

参数训练改善模型分数；校准拟合分数的系统性偏差；阈值选择确定误判和弃权的取舍。校准与阈值应在独立留出数据上拟合或选择，最终在未参与选择的测试数据上报告。当前数学基线不包含额外校准变换；训练后加入校准必须明确作用位置、参数版本及对一致性的影响。

## 8. 扩展：可训练的动态阈值门控（候选，未实现）

### 8.1 定义

令 h 为第 7.3 节同一次前向计算产生的隐藏表示，φ 为新增门控参数。定义：

$$(a_U(x),a_Y(x))=g_\phi(h),\qquad
\tau_U(x)=\sigma(a_U(x)),\quad\tau_Y(x)=\sigma(a_Y(x))$$

动态阈值决策定义为：

$$D_{\theta,\phi}(x)=\begin{cases}
U,&u\geq\tau_U(x),\\
Y,&u<\tau_U(x)\ \land\ q\geq\tau_Y(x),\\
N,&u<\tau_U(x)\ \land\ q<\tau_Y(x).
\end{cases}$$

业务输出仍为 (D,u,c)，c 根据最终选择的 Y/N 计算；门控不重写原始信念。诊断记录额外保留门控版本、a_U/a_Y 及实际 τ_U(x)/τ_Y(x)。固定阈值是 g_φ 输出常数的特例。

在实际实现中可直接比较 r≥a_U、d≥a_Y，避免 sigmoid 饱和影响阈值比较。g_φ 必须产生有限值；非有限值属于计算错误。

### 8.2 门控输入与结构

g_φ 可使用小型 MLP 读取 h。只有需要重新整合多个 token 表示时，才考虑注意力层或额外 Transformer；这不是本方案的必选组件。门控不需要第二次基模推理，但有额外参数和计算开销，须独立测量。

h 比三个 logits 包含更多潜在信息，门控可利用这些信息选择作答策略；这不构成自动识别错误或获得真实概率的保证。若需要任务成本等额外输入，必须将其明确写入门控契约，不能隐含依赖未记录的运行状态。

### 8.3 分数与阈值的可辨识性

决策实际只取决于：

$$r-a_U(x),\qquad d-a_Y(x)$$

若主干分数与门控同时自由训练，仅监督最终决策，模型既可改变信念分数，也可通过移动阈值达到同一答案。最终准确率提升不能单独证明原始信念质量改善。因此第 7.8 节的信念目标与门控的行动目标必须分开定义、分别评估。

动态阈值不负责消除高 u 与极端 q 的一致性问题，也不自动等同于概率校准。

### 8.4 训练与评估边界

可辨别收益的候选实验顺序是：先训练并固定信念模型 θ，再训练门控 φ；在相同作答覆盖率下比较错误率，或在相同错误率目标下比较作答覆盖率。需同时报告 Y/N 两类错误、不必要弃权以及分任务表现，避免仅通过扩大弃权范围获得表面改进。

硬阈值不提供常规可用梯度。若训练 φ，必须另行选择有监督门控目标、可微代理或基于结果反馈的策略优化；当前尚未选定其中一种，不将硬决策公式本身描述成完整训练算法。若未来联合训练 θ 与 φ，应保留信念监督与一致性约束，并与固定阈值及分阶段训练对照。

动态门控及三态模型均无运行效果证据。本次文档定义可复用的数学接口，不启动训练、不下载新权重，也不改变现有服务。
