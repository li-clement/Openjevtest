# 布尔、单选与多选推理方案

更新日期：2026-09-28。本文确定首版推理设计及工程约定，不表示新模式已经实现。

## 状态与范围

| 模式 | 设计 | 实现与验证 |
|---|---|---|
| 布尔 | 一对标签，sigmoid 分数差 | 已实现；已有 HTTP 和前向对照记录 |
| 单选 | K 个标签，候选内 softmax，选择一项 | 尚未实现或验证 |
| 多选 | 同一答案位置的 K 对标签，各自 sigmoid，再按阈值选集合 | 尚未实现或验证 |

当前 POST `/v1/decide` 仍只接收原有 query、criterion、image，返回布尔结果。本文不新增实际 API 字段、路由或运行代码。数学定义见 [数学模型](mathematics.md)。

## 统一执行结构

1. 应用提供图文材料、评价标准和业务候选；服务内置按模式区分的系统提示词。
2. 程序分配内部标签，校验 tokenizer，保存业务 ID 与 token ID 映射。
3. 受控模板展示全部候选描述和标签含义，结束于首答案位置；关闭思考。
4. 复用模型权重执行一次 prefill，使用原输出头得到该位置 logits。
5. 按模式提取、归一化并形成决策；结果按业务 ID 返回，不泄露内部字母作为业务身份。

多选的首版主路线是一次共享前向的成对读出，不是 K 次完整 Y/N 问答，也不枚举所有答案组合。不新增未训练的输出头参数。

## 首版工程约定（待实现）

### 候选与标签

- 单选至少 2 项，多选至少 1 项；每项包含唯一、非空的字符串 ID 和非空描述。完全重复的 ID 拒绝，不自动改名或合并；描述重复不代表业务 ID 相同。
- 标签池的候选顺序为 `A–Z`、`a–z`。按固定 tokenizer 验证其为可往返单 token、token ID 互异、且不是特殊 token；只使用通过验证的标签。校验结果随模型/tokenizer 版本固定，不把 52 项当成通用保证。
- 设可用标签数量为 L：单选上限 L，多选上限 floor(L/2)。超过上限直接报告输入错误，不静默分组、截断或增加模型调用。
- 候选按业务 ID 的 Unicode 码点字典序分配标签，以便展示顺序变化时映射可保持固定；展示顺序仍可按请求提供的顺序。多选按标签池相邻两个标签分配正/负标签。
- 映射必须显式出现在模型可见的上下文中。单 token 资格由程序检查，不是由提示词保证；首答案位置的模板适配需对每个底座验证。

### 分数与决策

- 布尔和多选默认阈值 0.5，严格大于才选中；等于时返回 false/不选中。现有布尔 API 阈值仍固定，不因本方案变更。
- 未来多选接受全局阈值及按业务 ID 的覆盖值：逐项覆盖优先，其次全局值，最后默认 0.5。只接受有限的 [0,1] 数值；覆盖表出现不存在的 ID 时拒绝。阈值不是概率校准参数。
- 单选比较未经舍入的 logits；完全同分时选业务 ID 字典序最小的一项。布尔保持既有同分返回 false 的规则，不通过通用单选平分规则改变它。
- 多选允许零项或全部选中；结果列表按请求中的候选顺序输出。候选数量限制、互斥约束、top-k 策略不自动添加。
- 分数用数值稳定算法计算，不先对 logits 作采样温度、top-k 或重复惩罚。非有限 logits 视为推理失败，不返回伪造的均匀概率或 false。
- 保留 `calibrated: false`，同时记录原始分数差、模型 revision、模板版本和实际阈值，便于复现。输出分数是命题判断的代理，不承诺真实事件概率或整体逻辑一致。

### 资源与异常

- 延续当前单张图片、串行模型推理、有限请求体/图片/token预算；候选与映射计入输入 token 预算。超过预算报错，不静默删除选项。
- 字段无效、重复 ID、阈值错误、标签不足应在推理前拒绝；模型失败与未选中明确分开。
- 推理次数定义为一次完整共享前向；输出头首版仍可计算全词表，再取所需标签。候选越多，输入和输出处理仍越长，不能宣称延迟与 K 无关。

## 待执行实验与验收

本次仅定义实验要求，未编写或运行新模式测试。

1. **机制**：检查所有标签配对、同一首答案位置、有限分数、单选归一化、多选每对归一化。验证没有进入生成循环或重复执行完整问答。
2. **多标签行为**：用明确的混合正负样例，以及全部成立/全部不成立样例，检查是否能同时表达多个高分与低分；增加图文对照，确认图像确实参与。
3. **一致性**：分别改变展示顺序和标签映射，按业务 ID 对齐，记录决策翻转及分数漂移；不只报告总体准确率。
4. **上下文影响**：只对含义不依赖其他候选的判断，检查增加无关候选的影响；相对选择任务不强求删除候选后结果不变。
5. **性能**：固定材料和图片，改变 K，分别测预热延迟、峰值内存、输入 token 数。逐项布尔问答可以作为实验对照，不作为主执行架构。
6. **有效性边界**：记录低概率标签对是否产生异常尖锐的比值。机制通过不代表分数已经有业务价值；若现成权重不能稳定遵循配对读出约定，明确报告实验失败，不以公式成立代替效果成立。

首轮实验先收集准确率、分数漂移与资源开销，尚未设业务验收阈值。训练、校准、联合概率建模与服务器性能不在本次落盘范围。
