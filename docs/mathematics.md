# 数学模型

更新日期：2026-09-28。布尔推理已实现并验证；单选为已记录的推理设计；多选为当前共享前缀分支方案，尚未实现，效率和一致性仍待验证。训练公式仅说明未来兼容性，不构成本次训练方案。

## 1. 统一输入及独立问题

统一输入包含内置系统提示词 S_mode、图文材料 X、评价标准 R、动态候选列表 C 和程序分配的标签映射 M：

$$P=\operatorname{Template}(S_{mode},X,R,C,M),\qquad z=\operatorname{LMHead}_{\theta}(h)$$

h 是对应判断上下文完成前向计算后最后输入位置的隐藏表示。布尔与单选分别读取一个答案位置；多选读取共享前缀后各分支自己的答案位置。系统提示词由服务按模式选择，不由请求覆盖。候选及其标签映射必须完整出现在输入中。

当前布尔模式令固定系统提示词为 S，待审文本与可选图像为 X，评价标准为 R。模板构造 P = Template(S, R, X, A=是, B=否)，并在助手开始回答的位置结束。评价标准由调用方的应用逻辑控制；待审材料不应成为执行指令。当前 API 每请求处理一个布尔问题。

若将来有多个标准 R_i，则每个标准构成独立输入 P_i。批处理可以提升效率，但不改变各问题定义，也不表示这些事件统计独立。

## 2. Prefill 与原有输出头

文本经过分词，图像经过视觉处理器。固定参数 θ 的模型前向处理全部输入，得到最后一个输入位置的最终隐藏表示 h：

$$h = \operatorname{Backbone}_{\theta}(\operatorname{Processor}(P))_{\mathrm{last}}$$

原模型的语言输出头给 token 评分：

$$z_A=w_A^\top h+b_A,\qquad z_B=w_B^\top h+b_B$$

这是模型训练好的线性评分，不是余弦相似度。无偏置的模型取 b=0。当前模型共享输入 embedding 与输出权重；代码调用原 embedding 的 as_linear，仅在最后位置计算词表分数，再提取 A/B。标签必须是经过 tokenizer 校验的不同单 token。

Prefill 已能产生第一个答案位置的分数。只有要继续生成第二个及后续 token 时，才需将选中 token 再送入模型。本 API 不需要这个生成循环。

## 3. 二选一概率与布尔结果

$$d=z_A-z_B$$

$$p_{yes}=\frac{e^{z_A}}{e^{z_A}+e^{z_B}}=\sigma(d),\qquad p_{no}=1-p_{yes}$$

这里是“给定输入，且下一个 token 被限定在 A/B 集合内”的条件概率。它忽略词表其余 token 的概率质量，不能直接解释为真实违规发生概率或答案正确率。

$$\hat y=\mathbf{1}[p_{yes}>0.5]=\mathbf{1}[d>0]$$

相等时返回 false。实现使用数值稳定的 sigmoid，不对分数加采样温度、top-k 或重复惩罚。运行错误与 false 分开处理。

## 4. 单选推理模型（已确定设计，尚未实现）

单选将布尔判断的两个答案扩展为 K 个互斥候选，仍然读取同一个“下一个 token”位置。它不要求增训、更换输出头或生成答案文本。当前 API 仍仅实现第 3 节的布尔输出。

### 4.1 业务选项与内部标签

令候选列表为：

$$C=[c_1,\ldots,c_K],\qquad c_i=(u_i,d_i),\qquad K\geq 2$$

其中 u_i 是唯一的业务 ID，d_i 是选项的语义描述。程序为每项分配不同的内部标签 ℓ_i，例如 A、B、C、D，并保存双向映射：

$$u_i\longleftrightarrow\ell_i\longleftrightarrow t_i$$

t_i 是标签对应的 token ID。标签不是新增 token，也不需要新增词表或权重；它们来自现有 tokenizer。程序必须验证每个标签编码后恰好是一个 token、解码可还原标签，且各 token ID 不同。候选数量受实际验证可用的标签数量限制，不假定任何模型都支持相同数量。

业务 ID 可以是 billing、shipping 等任意应用标识，不要求它们本身是单 token。例如：

| 业务 ID | 语义描述 | 程序分配的内部标签 |
|---|---|---|
| billing | 账单问题 | A |
| shipping | 物流问题 | B |
| technical | 技术问题 | C |

### 4.2 输入组装

固定系统提示词 S_choice 规定任务是单选、只回答内部标签，以及待审材料不构成指令。本次评价标准、完整候选及标签含义由程序写入受控请求模板：

$$M=[(\ell_1,d_1),\ldots,(\ell_K,d_K)]$$

$$P=\operatorname{Template}(S_{choice},R,X,M)$$

标签与含义必须在模型可见的提示词中明确对应；“标签是单 token”由 tokenizer 校验保证，不能靠系统提示词保证。完整候选列表参与模型判断，不把每个选项从上下文中单独拿出来判断。

### 4.3 同一答案位置的评分与归一化

沿用第 2 节的前向路径，得到最后输入位置的隐藏表示 h 和原输出头的词表分数 z。提取每个标签的分数：

$$s_i=z[t_i]=w_{t_i}^{\top}h+b_{t_i}$$

在 K 个候选之间做 softmax；为数值稳定，计算时减去最大分数 m：

$$m=\max_j s_j,\qquad p_i=\frac{\exp(s_i-m)}{\sum_{j=1}^{K}\exp(s_j-m)}$$

$$\sum_{i=1}^{K}p_i=1,\qquad \hat i\in\operatorname*{arg\,max}_i p_i$$

一次完整输入的 prefill 即可取得所有候选的分数，不需要为 K 个选项分别执行 K 次完整前向。输出的业务选项为对应的业务 ID，而不是内部字母；各项分数也按业务 ID 返回。若最高分完全相同，首版设计选择业务 ID 按 Unicode 码点字典序最小的一项；该规则不依赖候选展示顺序，但不能消除模型本身的顺序偏差。

建议响应语义为：

```json
{
  "choice": "billing",
  "probabilities": {"billing": 0.80, "shipping": 0.05, "technical": 0.15},
  "calibrated": false
}
```

这些值表示给定当前输入、且下一个 token 被限制在内部标签集合中时的条件概率，不能直接当作现实事件概率或正确率。系统必选一项；若允许“都不符合”或“信息不足”，调用方需将它明确列入候选，并给出判定含义。

布尔判断是 K=2 的特例：A=是、B=否时，p_A=σ(s_A−s_B)。当前布尔实现相等时返回 false，扩展单选时需保留该已存在的行为边界。

### 4.4 顺序和编码的一致性边界

对语义不依赖选项顺序的任务，换序或更换内部标签后，按业务 ID 对齐的结果应保持一致。若 π 表示重排，理想的分数输出满足排列等变性：

$$f(X,R,\pi C)=\pi f(X,R,C)$$

这是待检查的性质，不是现有模型或 softmax 自动提供的保证。选项位置、编码和完整候选集合均可能影响模型分数；特别是在平分情况下，确定性选取一项也不自动保证排列等变性。当前尚未实现针对这些性质的系统检查或训练约束。

## 5. 多选：共享前缀，每项独立 Y/N（当前方案，尚未实现）

### 5.1 公共上下文与候选问题

令 C=[c_1,…,c_K]，K≥1，每项包含唯一业务 ID u_i 与语义描述 d_i。所有分支保留完整候选上下文，在相同规则下分别判断某项是否应该入选，不让分支看到其他分支的答案。

对语义不依赖列表顺序的任务，程序按业务 ID 的 Unicode 码点字典序规范化候选列表：

$$C^*=\operatorname{Canonicalize}(C)$$

构造公共前缀 P_0，再构造各候选的问题后缀 Q_i：

$$P_0=\operatorname{PrefixTemplate}(S_{multi},X,R,C^*)$$

$$Q_i=\operatorname{QuestionTemplate}(u_i,d_i,\text{Y=应选中，N=不应选中})$$

语义上，每个完整分支输入为 P_i=P_0\oplus Q_i。所有分支使用同一对 Y/N token ID，且须校验它们为不同、可往返的非特殊单 token。不需要为不同候选分配不同的输出标签。

P_0 和 Q_i 表示模型实际输入 token 序列的切分，不是随意拼接的字符串。实现必须确认各完整聊天模板/图片处理结果拥有相同的 token 前缀及相同的位置元数据；若字符串分词边界改变，须退回实际共同 token 前缀。分支答案位置位于各自助手开始回答处，关闭思考。

### 5.2 缓存与隔离分支计算

公共前缀执行一次，保留可继续计算的完整状态：

$$\mathcal K_0=\operatorname{PrefillState}_{\theta}(P_0)$$

各分支从逻辑上独立的相同初始状态出发：

$$h_i=\operatorname{Forward}_{\theta}(Q_i;\operatorname{Fork}(\mathcal K_0))_{\mathrm{last}}$$

$$z_i=\operatorname{LMHead}_{\theta}(h_i)$$

Fork 表示分支隔离，并不要求物理复制全部缓存。支持只读共享/写时复制的后端可共享前缀存储；分支追加内容、位置计数和可变状态必须互不污染。对 Qwen3.5 等混合架构，状态不只包括注意力 KV，还包括其他层所需的循环状态等，必须完整处理。

分支可按内存预算串行、分批或并行执行。批处理和树状打包属于执行优化，不改变每个分支的是非问题语义；树状注意力不自动覆盖混合架构状态。当前尚未实现这些路径，也没有测得加速比。

### 5.3 分支评分与集合输出

在第 i 个分支自己的首答案位置，读取相同的 Y/N token：

$$\Delta_i=z_i[t_Y]-z_i[t_N]$$

$$p_i=\sigma(\Delta_i)=\frac{\exp(z_i[t_Y])}{\exp(z_i[t_Y])+\exp(z_i[t_N])}$$

各分支内部 yes/no 合计为 1，各候选的 p_i 不要求合计为 1。p_i 是给定完整分支上下文、限定下一个 token 为 Y/N 时的条件分数，作为当前候选入选判断的代理；未经校准，不承诺等于真实事件概率或正确率。

$$\hat y_i=\mathbf 1[p_i>\tau_i],\qquad \hat S=\{u_i:\hat y_i=1\}$$

默认 τ_i=0.5，相等时不选中；允许空集合与全部选中，不自动强制 top-k。输出按业务 ID 汇总，例如（仅展示语义，不是当前 API）：

```json
{
  "selected": ["insult", "threat"],
  "scores": {"insult": 0.90, "threat": 0.80, "personal_data": 0.10},
  "thresholds": {"insult": 0.5, "threat": 0.5, "personal_data": 0.5},
  "calibrated": false
}
```

独立执行分支不意味着候选事件统计独立。它们均读取完整候选上下文，但逐项判断不保证互斥、数量限制等集合关系；不提供完整联合分布，也不能将各项分数直接相乘作为联合概率。

### 5.4 计算量与等价性要求

计算目标是“一次公共前缀 + K 个问题后缀”，不是一次前向同时得到所有结果：

$$T_{serial}\approx T_{prefix}+\sum_i T_{suffix,i}$$

此式仅表示串行工作分解，不是测得的运行时间。各后缀仍需读取公共历史并通过模型各层，批量执行也不会消除这些计算。收益取决于公共前缀长度、候选数、缓存复制成本、图片处理复用和后端内核效率。候选列表本身也使公共前缀随 K 增长。

正确缓存复用的目标是：各分支 logits 与分别处理完整 P_i 的参考路径，在声明的数值容差内一致；以实际测试确认，不能仅凭缓存命中判定正确。整个过程不采样答案、不将某分支生成的答案接入其他分支，也不枚举所有答案组合。

### 5.5 请求换序与位置偏好的边界

若业务 ID、描述、材料和规则不变，仅输入候选的排列变化，规范化后 P_0 和各 Q_i 相同。在确定性执行和相同数值路径条件下，按业务 ID 对齐的分数应相同。内部调度采用规范顺序，结果再映射到调用方顺序。

这只消除调用方排列变化造成的输入差异，不证明模型没有位置偏好，也不保证改名、改写描述、增加候选后分数不变。模型仍看到一种固定的线性顺序。语义明确依赖原始列表顺序的任务不适用此规范化约定，不应静默改写任务。

## 6. 检查机制与未来训练接口（尚未实现）

当前重点是分支隔离、缓存路径与完整输入路径的一致性、图文参与、请求换序稳定性及实际效率。更换规范顺序、改写候选等属于独立的模型敏感性实验，不作为规范化自动保证。

如未来进行增训，可直接使用各分支读出的 p_i 与标注 y_i：

$$\mathcal L_{branch}=-\sum_i[y_i\log p_i+(1-y_i)\log(1-p_i)]$$

这只是与推理接口兼容的候选目标，不是已确定训练方案。可独立预留校准与阈值选择：

$$p_i=\sigma(\Delta_i/T_i+\beta_i),\qquad T_i>0$$

当前方案 T_i=1、β_i=0。模型训练更新 θ、校准拟合 T/β、业务阈值选择调整 τ；三者不同。训练损失不自动保证泛化或概率校准。业务关系可在规则中明确，但跨分支逻辑一致性仍需评估。
